## Summary
All four simulators keep "pick a selection" separate from "apply verbs to it", but each does it differently. Metastone/Spellsource pass one resolved `target` down to child spells. Fireplace passes the picked entity into `.then()` callbacks as event args. SabberStone stores the pick in a shared `TaskStack.Playables` and later tasks read it as `EntityType.STACK`.

For resolution-time choices, the main differences are where the options live while the player decides and what happens to the cards not chosen:
- **SabberStone** moves the real cards to SETASIDE and leaves the unchosen ones there. This matches hearthstone.wiki.gg's note on Tracking (Classic).
- **Fireplace** leaves Tracking's cards in the deck during the choice, then removes the unchosen ones from the game.
- **Metastone** sends all three Tracking cards to the graveyard before the choice.
- **Spellsource** always shows *copies* in a `DISCOVER` zone and acts on the chosen card through its id or a reference.

None of them stores a lasting "player has seen this deck card" fact.

## Findings

### Q1 — Several effects on one selection

1. **Metastone: the outer spell picks once, and children inherit that target unless they name their own.** In `game/src/main/java/net/demilich/metastone/game/spells/Spell.java`, `cast()` filters the targets and, when `RANDOM_TARGET` is set, makes one pick: `if (validTargets.size() > 0 && desc.getBool(SpellArg.RANDOM_TARGET)) { Entity target = SpellUtils.getRandomTarget(validTargets); castForPlayer(...target); }`. `MetaSpell.onCast` then runs every child with that same `target`: `for (SpellDesc spell : (SpellDesc[]) desc.get(SpellArg.SPELLS)) { SpellUtils.castChildSpell(context, player, spell, source, target); }`. `SpellUtils.castChildSpell` only uses the parent's target when the child has none: `EntityReference targetReference = spell.getTarget(); if (targetReference == null && target != null) { targetReference = target.getReference(); }`. So a child that declares its own `"target"` drops the shared pick. The factory `MetaSpell.create(EntityReference target, boolean randomTarget, SpellDesc... spells)` exists for this pattern. [Spell.java](https://raw.githubusercontent.com/demilich1/metastone/master/game/src/main/java/net/demilich/metastone/game/spells/Spell.java), [MetaSpell.java](https://raw.githubusercontent.com/demilich1/metastone/master/game/src/main/java/net/demilich/metastone/game/spells/MetaSpell.java), [SpellUtils.java](https://raw.githubusercontent.com/demilich1/metastone/master/game/src/main/java/net/demilich/metastone/game/spells/SpellUtils.java)
   - **No real card JSON found (UNVERIFIED).** I could not find a card file that gives one random minion two effects: code search (grep.app, sourcegraph) was blocked, and the Spellsource `develop` tree has no Hearthstone card files. The JSON below is my own illustration of the shape the code accepts, not a quoted card:
     `{"class":"MetaSpell","target":"FRIENDLY_MINIONS","randomTarget":true,"spells":[{"class":"BuffSpell","attackBonus":2,"hpBonus":2},{"class":"AddAttributeSpell","attribute":"TAUNT"}]}`
2. **Spellsource keeps the same model and documents it.** The `RANDOM_TARGET` doc in `SpellArg.java` says: "indicates that a random single target from the list of filtered targets should be cast on by this spell". The `TARGET` doc says it overrides "the target received from the parent". `SPELL` is described as cast "with `EntityReference#OUTPUT` set to the result of the parent spell's effect", which is a second way to chain onto a result. Spellsource's `MetaSpell` adds `howMany` and passes a `CARD` argument down to children ("This allows DiscoverSpells to correctly use MetaSpell"). [SpellArg.java](https://raw.githubusercontent.com/hiddenswitch/Spellsource/develop/spellsource-game/src/main/java/net/demilich/metastone/game/spells/desc/SpellArg.java), [MetaSpell.java (Spellsource)](https://raw.githubusercontent.com/hiddenswitch/Spellsource/develop/spellsource-game/src/main/java/net/demilich/metastone/game/spells/MetaSpell.java)
3. **Fireplace: `.then()` callbacks receive the picked entity as event args.** In `fireplace/actions.py`, `TargetedAction._trigger` does, for each resolved target: `ret += source.game.queue_actions(source, [action], event_args=[target] + target_args)`. `ActionArg.evaluate` returns `source.event_args[self.index]`, so `X.TARGET` inside a callback is the entity that was already picked. Real card, `fireplace/cards/dragons/warrior.py`, Galakrond, the Unbreakable ("Draw 1 minion. Give it +4/+4."): `play = ForceDraw(RANDOM(FRIENDLY_DECK + MINION)).then(Buff(ForceDraw.TARGET, "DRG_650e"))`. Here one random pick feeds both draw and buff. Writing `play = A, B` instead runs the actions one after another, and each evaluates its own selector, so two `RANDOM_*` selectors would pick separately (UNVERIFIED by test; inferred from `get_targets`). [actions.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/actions.py), [dragons/warrior.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/cards/dragons/warrior.py)
4. **SabberStone: the selection lives in `TaskStack.Playables` and later tasks read it as `EntityType.STACK`.** `RandomTask.Process` overwrites the stack: `stack.Playables = _amount == 1 ? new[] {entities[game.Random.Next(entities.Count)]} : ...ChooseNElements(_amount, game.Random);`. In `ComplexTask.Create(...)`, each later task reads `EntityType.STACK`. [RandomTask.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/Tasks/SimpleTasks/RandomTask.cs), [TaskStack.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/Model/TaskStack.cs)
   - **Y'Shaarj (OG_042), one pick and two verbs:** `new IncludeTask(EntityType.DECK), new FilterStackTask(SelfCondition.IsMinion), new RandomTask(1, EntityType.STACK), new RemoveFromDeck(EntityType.STACK), new SummonTask()`. [OgCardsGen.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/CardSets/OgCardsGen.cs)
   - **Brawl (EX1_407), "the chosen one" vs "the others":** `new RandomTask(1, EntityType.ALLMINIONS), new IncludeTask(EntityType.ALLMINIONS, new[] { EntityType.STACK }), new DestroyTask(EntityType.STACK)`. The second `IncludeTask` argument excludes the current stack, which turns the pick into its complement. [Expert1CardsGen.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/CardSets/Standard/Expert1CardsGen.cs)
   - **Mind Control Tech (EX1_085):** the same pick goes to `ControlTask(STACK)` or `DestroyTask(STACK)` depending on a flag.

### Q2 — Tracking and Dredge

5. **Card text.** Classic Tracking's text appears in Metastone's `spell_tracking.json` as "Look at the top three cards of your deck. Draw one and discard the others." SabberStone's DS1_184 comment has the same wording with "top 3". The current Legacy version on hearthstone.wiki.gg reads "Discover a card from your deck." The wiki's Tracking (Classic) notes say the other cards "are not discarded, but left in the Setaside Zone", and the chosen card reaches the hand only at end of Sequence. Dredge: "Look at the bottom 3 cards of your deck. Put one on top." It does not shuffle, and the leftmost option is the bottom-most card. I could not quote the Classic text from the wiki page itself (UNVERIFIED there). [Tracking](https://hearthstone.wiki.gg/wiki/Tracking), [Tracking (Classic)](https://hearthstone.wiki.gg/wiki/Tracking_(Classic)), [Dredge](https://hearthstone.wiki.gg/wiki/Dredge)
6. **Metastone Tracking: all three cards go to the graveyard first, then a card is received by id.** `cards/src/main/resources/cards/basic/hunter/spell_tracking.json` is `"spell": {"class": "DiscoverDrawSpell", "spell": {"class": "ReceiveCardSpell"}}`. `DiscoverDrawSpell` loops `Card card = player.getDeck().peekFirst(); context.getLogic().removeCardFromDeck(player.getId(), card);`. `removeCardFromDeck` logs "moved from the DECK to the GRAVEYARD" and adds the card to the graveyard. `SpellUtils.getDiscover` builds one `DiscoverAction` per card using `spell.addArg(SpellArg.CARD, card.getCardId())`. So the chosen card is re-received **by card id**: one spell per option is the chosen card's outcome, and the graveyard is the others' outcome. Whether this hands over the same object or a catalogue copy is UNVERIFIED; `GameContext.getCardById` → `CardCatalogue.getCardById`. [spell_tracking.json](https://raw.githubusercontent.com/demilich1/metastone/master/cards/src/main/resources/cards/basic/hunter/spell_tracking.json), [DiscoverDrawSpell.java](https://raw.githubusercontent.com/demilich1/metastone/master/game/src/main/java/net/demilich/metastone/game/spells/DiscoverDrawSpell.java), [GameLogic.java](https://raw.githubusercontent.com/demilich1/metastone/master/game/src/main/java/net/demilich/metastone/game/logic/GameLogic.java)
7. **Spellsource Dredge: real cards stay in the deck and copies are shown.** `DredgeSpell.java` takes `deck.subList(0, count)` (index 0 is the bottom). It builds a `DiscoverSpell` desc with `EXCLUSIVE=true` and `PutDeckTopSpell`, then calls `SpellUtils.discoverCard`, which "always work[s] with a copy". It then finds the real card by id ("Find the actual card in the deck (discover works with copies)") and does `deck.remove(actualCard); deck.addLast(actualCard);`. The unchosen cards are never touched. Side effect: `postDiscover` moves the copies to `REMOVED_FROM_PLAY`. Possible flaw: matching by `getCardId()` grabs the first card with that id among the bottom 3, which can be the wrong copy if duplicates differ (e.g. buffed). Spellsource Tracking: UNVERIFIED (no Hearthstone card JSON in the `develop` tree). Spellsource marks Metastone's `DiscoverDrawSpell` deprecated ("Use `DiscoverSpell` instead"). [DredgeSpell.java](https://raw.githubusercontent.com/hiddenswitch/Spellsource/develop/spellsource-game/src/main/java/net/demilich/metastone/game/spells/DredgeSpell.java), [SpellUtils.java (Spellsource)](https://raw.githubusercontent.com/hiddenswitch/Spellsource/develop/spellsource-game/src/main/java/net/demilich/metastone/game/spells/SpellUtils.java), [Deprecated list](https://www.playspellsource.com/javadoc/deprecated-list.html)
8. **Fireplace Tracking: cards stay in the deck while the player chooses.** `fireplace/cards/classic/hunter.py` has `play = GenericChoice(CONTROLLER, FRIENDLY_DECK[-3:])`; `deck[-1]` is the top, as `Draw` uses `target.deck[-1]`, and commit ac75d0b "Top of deck" changed `[:3]` to `[-3:]`. `GenericChoice.choose` sets the chosen card to `_card.zone = Zone.HAND` directly, not through `Draw`, so draw scripts and broadcasts don't fire. If the hand is full it calls `discard()`. Every other card gets `_card.discard()`. `Discard.do` broadcasts the discard event and then sets `target.zone = Zone.REMOVEDFROMGAME`. It only sets `DISCARDED` and runs the card's own discard script when `old_zone == Zone.HAND`. Dredge: not found; the README says the card set is current to "Patch 17.6.0.53261", which is before Voyage to the Sunken City (likely not implemented, UNVERIFIED). [hunter.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/cards/classic/hunter.py), [commit ac75d0b](https://github.com/jleclanche/fireplace/commit/ac75d0b6411e78070b8afc143547c132900572d7), [fireplace README](https://github.com/jleclanche/fireplace)
9. **SabberStone Tracking: real cards move to SETASIDE and the unchosen ones stay there.** In `CoreCardsGen.cs` DS1_184: `IPlayable entity = deck.Remove(deck.TopCard); ids.Add(entity.Id); p.Controller.SetasideZone.Add(entity);`, then `Actions.Generic.CreateChoice(p.Controller, p, ChoiceType.GENERAL, ChoiceAction.HAND, ids)`. On pick, `case ChoiceAction.HAND: if (RemoveFromZone(c, playable)) { AddHandPhase.Invoke(c, playable); }`. Nothing touches the other ids, so they stay in SETASIDE, which matches the wiki note. A `ChoiceAction.TRACKING` enum value exists, but its handler is commented out. Dredge is not implemented (the card sets end around Uldum/Dragons). [CoreCardsGen.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/CardSets/Standard/CoreCardsGen.cs), [Choose.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/Actions/Choose.cs), [Choice.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/Model/Choice.cs)

### Q3 — Discover options from a card pool

10. **Spellsource `DiscoverSpell`: option entities are temporary display copies in a `DISCOVER` zone.**
    - **Pool:** `cards` + `cardSource` + `cardFilter`, picked without replacement, weighted when the source `HasWeights`.
    - **Option entities:** catalogue entries (id −1) are cloned. Each option is then `Card copy = originalCard.getCopy(); copy.setId(context.getLogic().generateId()); ... copy.moveOrAddTo(context, Zones.DISCOVER);`.
    - **Each option carries a pre-built spell:** chosen spell = `chosenSpellTemplate.addArg(SpellArg.CARD, originalCard.getCardId())`, or with `exclusive`, `addArg(SpellArg.TARGET, originalCard.getReference())`. The unchosen cards get `SPELL2` through the same rule. These are joined into one `DiscoverAction`.
    - **After the pick:** `postDiscover` says: "Cards that are being discovered are always copies, so they are always removed from play afterwards" (→ `REMOVED_FROM_PLAY`). The result is a fresh card made by e.g. `ReceiveCardSpell`, which is the default when no spell is given.
    - **Discover from deck:** the Javadoc says: "Other card sources, like `DeckSource`, will reference the actual cards in the player's deck. Discovers **always** present copies… To perform the spell on the **actual** card, set `EXCLUSIVE` to `true`"; `exclusive` with a catalogue source throws an exception.
    - **Unchosen hook:** `SpellArg.UNCENSORED`/attribute marks DISCOVER-zone cards as visible to the opponent, and there is a Rohei-style aura hook for not-chosen cards.
    
    [DiscoverSpell.java](https://raw.githubusercontent.com/hiddenswitch/Spellsource/develop/spellsource-game/src/main/java/net/demilich/metastone/game/spells/DiscoverSpell.java)
11. **Fireplace `Discover`: options are real entities created in SETASIDE, and the chosen entity itself goes to hand.** `Discover.get_target_args` builds `picker = self._args[1] * 3`, weights neutral and class cards, and calls `picker.evaluate(source)`. `weighted_card_choice` ends with `return [source.controller.card(card, source=source) for card in chosen_cards]`, and `Player.card(self, id, source=None, parent=None, zone=Zone.SETASIDE)` defaults to the SETASIDE zone. The `DISCOVER` helper in `cards/utils.py` is `Discover(CONTROLLER, *args).then(Give(CONTROLLER, Discover.CARD))`, so that SETASIDE entity is what moves to hand. `Discover.choose` doesn't move the others, so they stay in SETASIDE. Discover-from-deck, Master's Call (`troll/hunter.py`): `entities = (RANDOM(DeDuplicate(FRIENDLY_DECK + MINION)) * 3).eval(...)`, then `yield GenericChoice(CONTROLLER, entities)`. These are real deck entities, so the unchosen ones are **removed from the game**. The wiki says deck discovers "draw the card", which implies the rest stay in the deck, so this looks like a fidelity gap (UNVERIFIED by test). [utils.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/utils.py), [player.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/player.py), [random_picker.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/dsl/random_picker.py), [cards/utils.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/cards/utils.py), [troll/hunter.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/cards/troll/hunter.py), [Discover wiki](https://hearthstone.wiki.gg/wiki/Discover)
12. **SabberStone `DiscoverTask`: card definitions become SETASIDE entities, and the follow-up is chosen by `ChoiceAction`.** `DiscoverType` (e.g. `DRAGON`, `DECK_MINION`, `OP_DECK`, `OWN_SPELL`) or criteria produce `Card[][]` pools. Static pools are cached in `CachedDiscoverySets`; deck-based types are not. `GetChoices(cardsToDiscover, 3, rnd)` returns definitions, and `Generic.CreateChoiceCards` instantiates them: `Entity.FromCard(c, p, new EntityData{{GameTag.CREATOR, source.Id},{GameTag.DISPLAYED_CREATOR, source.Id}}, c.SetasideZone)`. The `Choice` stores ids, a `ChoiceAction` (HAND/SUMMON/CAST/SPELL_RANDOM/HEROPOWER/…), and an `AfterChooseTask`, run as `Process(game, c, source, playable /*chosen as target*/, new TaskStack{Playables = EntityStack...})`. Chained discovers use `NextChoice`/`TryPrepare()`, which creates the entities lazily. Unchosen cards stay in SETASIDE. `DECK_MINION`/`OP_DECK` read `DeckZone...Select(p => p.Card)`, i.e. **definitions, so they create copies** ("Discover a copy"). True draw-from-deck is hand-coded: `SpecificTask.MastersCall` moves the real deck entities to SETASIDE and calls `Generic.CreateChoice(..., ChoiceAction.HAND, ...)`. The unchosen ones are not visibly returned to the deck (UNVERIFIED). [DiscoverTask.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/Tasks/SimpleTasks/DiscoverTask.cs), [SpecificTask.cs](https://raw.githubusercontent.com/HearthSim/SabberStone/master/SabberStoneCore/src/Tasks/SpecificTask.cs)

### Q4 — Fireplace `GenericChoice` vs `Discover`

13. **The shared abstraction is the open choice object on the player, not a common base class.**
    - **Common interface:** `Choice(TargetedAction)` sets `player.choice = self`, `self.cards`, `min_count = max_count = 1`. Its `choose(card)` checks `card in self.cards`, clears `player.choice`, and runs the saved callbacks with `[self.cards, card]`.
    - **`GenericChoice(Choice)`** adds the outcomes: chosen → HAND (or PLAY for a hero power, discard if the hand is full), others → `_card.discard()`.
    - **`Discover`** is a separate `TargetedAction`, not a `Choice` subclass. It has the same duck-typed interface (`player.choice`, `cards`, `min/max_count`, `choose`). Its callbacks get `[self.target, self.cards, card]`, and it moves nothing itself; the `.then(Give(...))` decides the chosen card's fate and the others stay in SETASIDE.
    - **`MulliganChoice`** uses the same interface with `max_count = len(hand)`.
    - **Pausing other actions:** `TargetedAction._trigger` defers other actions while a choice is open: `if source.controller.choice: self.choice_callback.append(lambda: self._trigger(i, source))`.
    
    [actions.py](https://raw.githubusercontent.com/jleclanche/fireplace/master/fireplace/actions.py)

### Q5 — Knowledge state after looking

14. **No simulator records lasting "player X has seen card Y" knowledge (partly UNVERIFIED, since I could not search all of each repo).**
    - **Spellsource** has visibility for the duration of a discover only: `UNCENSORED` — "When set on a card in the `Zones#DISCOVER`, indicates the card should be turned over and visible to the discovering player's opponent". It is removed after the discover. `Attribute.java` has no SEEN/KNOWN attribute. Dredge leaves no mark on the cards it looked at. [Attribute.java](https://raw.githubusercontent.com/hiddenswitch/Spellsource/develop/spellsource-game/src/main/java/net/demilich/metastone/game/cards/Attribute.java)
    - **Fireplace** has only `dump_hidden` serialization, which depends on the zone.
    - **SabberStone** has only the `PowerHistory` log, plus `CREATOR`/`DISPLAYED_CREATOR` tags on created entities.
    - **Knowledge is implicit in position.** In Fireplace's and Metastone's Tracking, looking ends with the cards leaving the deck. Dredge's knowledge ("the top card is X") is implied only by deck order.
